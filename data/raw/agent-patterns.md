# Agent 设计要点

## ReAct 与 Plan-and-Execute 的区别

ReAct 是边想边做：每一步把"观察"喂回模型，由模型决定下一步调什么工具或是否收尾。优点是遇到意外能改路线，缺点是多轮调用、延迟高、容易绕圈。

Plan-and-Execute 是先一次性生成完整计划再逐步执行。优点是调用次数少、可控；缺点是计划错了就全错，中途出现新信息不容易调整。

实践中常用折中：先给一个粗计划，执行时允许局部重规划。简单任务用 ReAct 就够了，别过早引入规划器。

## 工具调用常见坑

工具描述写得含糊，模型就选错工具；参数没有类型和范围校验，模型会传非法值；工具返回的内容过长，一次就把上下文吃掉。对策：工具描述写清"什么时候该用、什么时候不该用"，参数做 schema 校验并给出错误提示，返回值做截断和摘要。

## 防止绕圈

记录已调用过的工具和参数组合，第二次相同调用直接拦截并提示模型"已调用过，请换思路或收尾"。同时设置最大步数上限，超限强制收尾并给出已有信息。

## 记忆分层

短期记忆是当前会话的消息列表，要处理压缩。长期记忆是跨会话的用户偏好和事实，需要抽取、去重、存储和召回四个环节，复杂度和短期记忆不是一个量级，不要一开始就做。
