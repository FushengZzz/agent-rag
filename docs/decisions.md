> 这份文件就是你面试被问"为什么这么设计"时的答案库。AI 生成的代码你能讲清，靠的就是它。

## 2026-11-11 用独立 venv，不用系统 Python

- **结论**：项目根目录 `.venv`，命令一律走 `.venv/Scripts/python.exe`。
- **为什么**：Git Bash 里 `python` 指向 `C:/msys64/ucrt64/bin/python.exe`，那个 Python **没有 pip**；而 pip 属于 `Programs/Python/Python312`。装包和运行会是两个解释器，必然 `ModuleNotFoundError`。
- **备选**：直接改 PATH / 用 conda。放弃：改 PATH 会影响别的东西（platformio 等），conda 对这个项目太重。

## 2026-11-11 embedding 用本地 bge-small-zh-v1.5，不用云 API

- **结论**：`sentence-transformers` + `BAAI/bge-small-zh-v1.5`，CPU 跑。
- **为什么**：DeepSeek 只提供对话模型，**没有 embedding 接口**（已确认）。本地模型免费、离线、无额度限制，中文效果够用；小模型延迟低，适合交互式问答。
- **备选**：硅基流动 bge-m3 / 阿里百炼 text-embedding-v3。放弃：多一个外部依赖和额度焦虑，开发期反而更容易卡住。**上线演示阶段可换大模型做对比实验**——这正好是简历里"评测"那一条的素材。

## 2026-11-11 生成用 deepseek-chat，reasoner 只作对比实验

- **结论**：Agent 主循环用 `deepseek-chat`（快、便宜、支持 Function Calling）。
- **为什么**：Agent 一轮要多次调用，reasoner 延迟高、成本高，交互体验差。
- **备选**：deepseek-reasoner。用途：只做"chat vs reasoner 在工具调用任务上的成功率/延迟/成本"对比实验，作为评测模块的一个数据点。

## 2026-11-13 切分按"段落聚合 + 标题强制断块"，不做固定窗口硬切

- **结论**：先按空行切段，再把段落累积到接近上限（450 字）才成块；**遇到 `##` 标题立刻断块**，保证"标题 + 本节正文"在同一块。超长段（> 450）才在段内硬切。
- **为什么**：固定窗口硬切会把句子切断，实测出现"块以『坏了语义单元』开头"——半句话都没了，标题和正文被拆到两块，检索必然不准。改按标题断块后，4 个测试问题全部命中正确 section（0.66–0.76），且与第二名有明显差距。
- **备选**：固定窗口 512 字 + overlap。放弃：语料是结构化 markdown，边界本来就在标题处，用窗口去猜边界是舍近求远。**如果是聊天记录、扫描件这类无结构文本，就必须回到固定窗口。**

## 2026-11-13 按字符数切，不引入 tokenizer

- **结论**：`CHUNK_SIZE = 450` 指的是**字符数**，不是 token 数。
- **为什么**：为了切分再装一个 tokenizer 依赖，收益极小。中文里 1 字≈1 token 量级，450 字离模型上下文上限很远，不会出问题。
- **代价（必须知道）**：英文/代码场景下字符与 token 比约 1:0.25，同一套参数会导致块明显偏小。**换成英文语料时要重新定参数，不是直接复用。**
- **备选**：tiktoken 精确计数。放弃：当前语料用不上，等接 PDF 或英文文档时再考虑。

## 2026-11-13 相邻块不做 overlap

- **结论**：块之间零重叠（`CHUNK_OVERLAP` 已删除）。
- **为什么**：按 section 切分时，边界本身就是完整语义单元，不需要重叠来补上下文。overlap 的价值主要在**固定窗口切分**时——那时边界是随机的，靠重叠兜底。而重叠的代价是同一段内容被重复编码、重复占用上下文窗口。
- **一句话版本（面试可直接说）**：*overlap 是给"不可靠的边界"兜底的，我的边界来自文档结构，所以不需要。*
- **备选**：块间重复最后一句。放弃：收益不明显，且会让引用脚注重复。

## 2026-11-14 embedding 收敛到 app/embedding.py 单例

- **结论**：所有编码统一走 `app.embedding.encode_docs` / `encode_query`，`QUERY_PREFIX` 只在这个模块定义一次。
- **为什么**：原来 `ingest.py` 和 `retrieve.py` 各写一行 `SentenceTransformer(...)`，W2 接入 `agent.py` 后会被同时 import，**一次启动加载两个模型实例**，内存翻倍、冷启动慢一倍。前缀常量重复定义还会导致"某处重复加前缀"这种极难排查的 bug。
- **备选**：每次用到时 new 一个模型。放弃：单个实例加载约 1–2 秒，且占用内存，重复加载没有收益。
